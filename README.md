# KaraokeTool

Create karaoke videos for carnival parodies. You supply a recording
and the official lyrics; KaraokeTool splits the song into an
instrumental and a vocal track, has Whisper transcribe the vocals,
lays the lyrics over that transcription word by word and renders a
karaoke video from it. A second text - the parody - can be placed on
exactly the same timing. On top of that, words left behind in a
purchased karaoke version (e.g. "oe", "koffie") can be tracked down
and attenuated by 25 dB instead of being removed.

**Current version: 1.0.** The whole path from recording to video
works: separating, transcribing, timing, adjusting things by hand
and rendering. The video is x264/AAC in yuv420p, so it simply plays
on any PC, phone or Apple device. There is a built-in test panel
that measures the automatic timing against hand-corrected timing
across a collection of real songs; that is the yardstick on which
every change is judged.

Whisper does not spell sounds consistently ("Kedeng kedeng" comes
out as GEDENGEDENG, KREEG ER EEN or KREGERING); the software
therefore learns the sound, not the spelling. For the attenuation,
phonetically similar sounds are clustered and shown with frequency,
confidence, average duration and average pause (handy for
recognising choruses), after which you choose which clusters get
attenuated; the rest of that pipeline works with clusters, not with
individual words. Original and karaoke are aligned automatically on
onsets, chroma, MFCC and cross-correlation, without assumptions
about BPM or bar length, using several offset regions per song; the
result is written to `output/uitlijning.json`. The chosen clusters
travel through that alignment to the karaoke and only those
fragments are lowered by `gain_db` (default -25 dB, not muted), with
crossfades (`fade_in_ms`/`fade_out_ms`); overlapping fragments are
merged. The export keeps the source format: for mp3 the same sample
rate, the same channels and the same bitrate mode (VBR quality or
nearest CBR bitrate) as the source, for wav as `karaoke_edit.wav`.
Note: the cache is wiped completely on startup and shutdown, so run
the steps within a single session ("Alles uitvoeren" runs them all
in one go).
CSV files use `;` as their separator (Excel-friendly).

## Analysis per music track

Every song title is a **self-contained project**: `input/<titel>`,
`output/<titel>` and `cache/<titel>` are kept apart. At the top of the
GUI you pick an existing project (button "Openen", open) or create a
new one ("Nieuw project"). Switching projects never moves files; an
existing project is opened, a new title starts out empty. That way
every song lives in its own folder and the main folders stay clean.

In the GUI (and through the `tracks` section in `config.json`) you
choose which tracks transcription and analysis apply to: the
original, the karaoke version, or both (the default). Analysing the
karaoke itself tracks down the **leftover words** that stayed in the
karaoke - the heart of this program. Clusters from the original are
projected through the alignment; clusters from the karaoke track sit
on the karaoke timeline already and are attenuated directly (step 3
is then unnecessary). Output goes to `output/origineel` and `output/karaoke`.

Wiping the cache on startup and shutdown can be switched on or off
in the GUI (on by default) and is stored in `config.json` under
`cache.wissen`.

## Official lyrics (strongly recommended)

Put the original lyrics in `input` as `lyrics.txt` (or pick the
file in the GUI). The original text leads: the lyrics are aligned
phonetically with the transcription word by word (even when the
spelling differs, such as `Kedeng Kedeng`, which Whisper heard as
`GEDENGEDENG` or `de trein`). That gives clusters the official
spelling as their name, finds target words Whisper wrote down
differently, and estimates missed choruses from the anchors around
them (label `TEKST (geschat)`). The alignment report is in
`output/origineel/songtekst_uitlijning.txt`; every extra fragment
can be checked in the fragment list.

## Sound clusters (the core of the program)

Step 2 builds candidate sounds from individual words and short word
groups, gives every sound a phonetic key tuned to sung Dutch (g=k,
d=t, h and r drop out, oe/oh/ooh count as the same) and groups
similar keys, including repetitions (GEDENGEDENG with GEDENG) and
contractions (KOFFIETHEE with KOFFIE). The result: `clusters.html`
(a report that opens in the browser automatically) and
`clusters.json` (all the data). For each cluster the HTML report
shows the name, variants, frequency, confidence, average duration
and pause, all timestamps, segment numbers and a sample text. In the
GUI the clusters appear with tick boxes; the suggestion is already
ticked and every change is saved immediately. Example:

    Cluster 1
      GEDENGEDENG  (2x)
      KREEG ER EEN  (1x)
      KREGERING  (1x)
      gevonden: 5 keer, confidence 0.90, duur 0.69 s, pauze 2.5 s

The `search_words` from `config.json` act as a suggestion for which
clusters are interesting - tune them per song (for Per Spoor, say,
`["kedeng", "oe", "oeh"]`); search words that do not fit give
suggestions that do not fit; your choice is saved in `project.json`.
Cluster behaviour can be set through the `cluster` section in
`config.json` (among others `similarity_threshold`, default 0.65:
lower = more aggressive merging).

## Installation

### 1. Python 3.12

Download it from <https://www.python.org/downloads/> and tick
**"Add python.exe to PATH"** during the installation.

### 2. ffmpeg

KaraokeTool uses `ffmpeg` and `ffprobe` for conversion and for reading
source properties (bitrate, sample rate, channels, VBR/CBR).

Install it with winget (recommended, from a command prompt):

    winget install Gyan.FFmpeg

Then close every command prompt and the program itself and start
again, otherwise the new PATH is not visible yet. Check with:

    ffmpeg -version
    ffprobe -version

**Alternative without PATH:** download a build from
<https://www.gyan.dev/ffmpeg/builds/> (ffmpeg-release-essentials.zip),
unpack the zip file and copy `ffmpeg.exe` and `ffprobe.exe` from the
`bin` folder into the `KaraokeTool\bin` folder. KaraokeTool finds
them there automatically.

### 3. KaraokeTool

Double-click `install.bat`. This creates a virtual environment (`venv`)
and installs all the packages from `requirements.txt`.

### 4. Whisper model

The first time you use "Detecteer woorden" (detect words; as of
version 0.2) Faster Whisper downloads the `large-v3` model
automatically (a few GB, one time only). An NVIDIA GPU speeds this up
considerably but is not required; without a GPU the model runs on the CPU.

## Usage

### Graphical interface (recommended)

Start `KaraokeToolGUI.bat`. The window offers:

- a file picker per input file: if `origineel` or `karaoke` is
  missing, pick an mp3/wav and it is **copied** into the `input`
  folder (the file you picked is left untouched);
- buttons for steps 1-5 and "Alles uitvoeren" (run everything);
- a progress bar during the Whisper step;
- the sound clusters found, with tick boxes; the suggestion is
  already ticked and every change is saved immediately;
- after step 4 a waveform of the edited karaoke with the attenuated
  fragments marked in red (planned: adding extra regions here
  yourself);
- a fragment list below the waveform: every attenuated fragment can
  be ticked or unticked (unticked = do not attenuate) and played back
  with a 1.5 s run-up; changes are re-applied and exported straight
  away;
- a separate **Karaokevideo** tab (video, kept apart from the audio
  editing, which is not always needed): choose the karaoke lyrics and
  logo, check the input, build the timing skeleton and render the
  video ("make a first render, then fine-tune");
- a message window; long steps run in the background so the window
  does not freeze.

### Input files

The file pickers in the GUI copy your choice into the project's input
folder, but you can also drop the files in `input/<titel>` yourself:

- `origineel.mp3` or `origineel.wav` - the original song
- `karaoke.mp3` or `karaoke.wav` - the karaoke version (only needed for
  the attenuation; for a video the program splits the original itself)
- `lyrics.txt` - the official lyrics
- `karaoke_text.txt` - the parody lyrics, if they have to run on the
  same timing

The result appears in `output/<titel>`: the karaoke video, plus
`karaoke_edit.mp3` (or `.wav`, depending on the input) if you used
attenuation. Log files are stored per day in `logs`.

## Configuration

All song-specific settings live in `config/config.json`:

    {
      "search_words": ["oe", "oeh", "woo", "oh", "koffie", "thee"],
      "gain_db": -25,
      "fade_in_ms": 70,
      "fade_out_ms": 60,
      "whisper": {
        "model": "large-v3",
        "device": "auto",
        "compute_type": "auto",
        "language": "nl"
      },
      "align": {
        "max_offsets": 4
      }
    }

- `search_words` - words that are attenuated in the karaoke
- `gain_db` - attenuation in dB (negative; default -25)
- `fade_in_ms` / `fade_out_ms` - crossfade times around each fragment
- `marge_ms` - extra attenuation before and after each fragment
  (default 0); raise it (to 120, say) if edges of words stay audible

For a different song, adjusting this file is enough; the code holds
no song-specific settings.

## Intermediate results and cache

`cache/project.json` holds every intermediate result of the session
(checksums, source properties, cluster selection, offsets);
`cache/transcriptie.json` contains the Whisper transcription. Within
a session Whisper therefore does not have to run again when you
repeat a step. On startup and shutdown the cache is wiped
completely: every session starts clean and Whisper runs afresh once
per session.

During the Whisper step the progress is shown (percentage and
seconds processed).

## Development

    venv\Scripts\python.exe -m pytest tests

Structure: `KaraokeTool.py` is the only entry point (with or
without `--gui`); all the logic sits in `modules/`. Orchestration
lives in `pipeline.py`; the GUI (`gui.py`, PySide6) is a thin shell
around it. The test panel (`test_panel.py`) runs the yardstick and
the trials; `tools/timing_regression.py` does the same from the
command line.

## Troubleshooting

**"faster-whisper is niet geïnstalleerd" while install.bat has been run**

1. Always start the program through `KaraokeToolGUI.bat` (not with a
   bare `python KaraokeTool.py`); only the bat file uses the virtual
   environment that holds the packages.
2. Check the installation from a command prompt in the project folder:

       venv\Scripts\python.exe -m pip show faster-whisper

   No output? Then the installation failed at the time. Run
   `install.bat` again; it now checks explicitly at the end whether
   all packages can be imported and shows the error message if not.
3. **Project folder moved or copied to another computer?**
   A virtual environment cannot be moved. Delete the `venv` folder
   and run `install.bat` again in the new location.

**ffmpeg not found:** see Installation above, or put `ffmpeg.exe`
and `ffprobe.exe` in the `bin` folder.

## Moving to another computer

Copy the project folder without `venv`, `cache` and `logs` and run
`install.bat` there. It now detects for itself whether Python 3.12
and ffmpeg are present and offers to install them through winget.

## Language

The interface language is Dutch by default; English is available
through the language selector (with a little flag) on the "Muziek
laden en analyse" (load music and analyse) tab. Your choice is
stored in `config.json` (`interface.taal`) and applied the next time
you start the program. Adding another language means adding one more
dictionary in `modules/translations.py`.

This is separate from the **audio language** - the language that is
sung - which Whisper detects automatically from the recording
itself.
